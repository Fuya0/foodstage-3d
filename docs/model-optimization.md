# Mobile model optimization

The original assets in `public/models/burger-*.glb` are immutable source files. Mobile copies in `public/models-mobile/` are generated by `scripts/optimize-models.mjs` with glTF-Transform CLI `4.5.1`:

```text
pnpm optimize:sample
pnpm optimize:models
```

The pipeline uses meshoptimizer at high level, welds and simplifies geometry to a 0.35 vertex ratio (error tolerance `0.0001`), quantizes attributes, downsizes textures to 1024×1024, and recompresses PNG textures as WebP. Scene flattening, joining, instancing and palette generation are disabled. It writes only `public/models-mobile/` and never overwrites `public/models/`.

```text
for %i in (0 1 2 3) do npm exec --yes --package=@gltf-transform/cli@4.5.1 -- gltf-transform inspect public/models/burger-%i.glb
for %i in (0 1 2 3) do npm exec --yes --package=@gltf-transform/cli@4.5.1 -- gltf-transform inspect public/models-mobile/burger-%i.glb
```

The sample `burger-0` inspection reports source mesh indices 255,074 / render vertices 855,981 and optimized mesh indices 247,311 / render vertices 270,518. The other models were generated with the identical deterministic settings.

## Runtime and validation

The optimized files declare `EXT_meshopt_compression`, `KHR_mesh_quantization`, and `EXT_texture_webp`. `src/scene/assets.ts` registers Three.js's bundled `MeshoptDecoder` before loading, and `GLTFLoader` natively supports WebP textures. All four generated files parsed successfully with `gltf-transform inspect` as glTF 2.0. Original source sizes remain 18,514,384; 17,235,596; 18,942,740; and 20,670,604 bytes.

The mobile tradeoff is deliberate: geometry is simplified and quantized, and textures are capped at 1024² WebP. This substantially reduces transfer and GPU memory. Subjective visual equivalence still needs browser pixel inspection and human sign-off during controller integration.
