# 嚼光：食物小游戏重构

用户已授权自行决定设计和实施，不要求中途询问方案。目标保留原有四阶段直接点吃与拖动观察，同时提供真正可进入的食物选择和设置。

## 体验

启动进入食物柜台，只有目前有资产的“经典汉堡”可选择。食物项展示真实汉堡缩略图和四阶段信息；点击“开始品尝”进入游戏，游戏顶部可回到选择及打开设置。游玩中有阶段轨迹和 8 口计数，主角依然是 3D 食物，无额外进食按钮。完成后可再吃一次或返回选择。

视觉语言：清爽的番茄红、叶绿、暖白与深色墨字；游戏像食物包装与纸质餐盘，而非空白宣传页或卡片墙。内容排布有明确的顶部导航、中央食物舞台、底部进度带。小屏为纵向游戏视图，保持食物优先；按钮仅用于命令、图标用于工具。

设置：系统减少动态效果可由本地设置覆盖；音效和触觉开关真实驱动 Web Audio / Vibration API；拖动灵敏度控制真实改变指针旋转增量。设置保存在 localStorage，缺少浏览器能力时不报错。设置对话框可从选择和游戏打开，焦点与 Escape 行为正确。

## 交互与几何

用固定外层锚点保持食物中心位于相机前，中心旋转组内将 GLB 内容平移 `-asset.center`。外层定位应吸收模型贴地的尺寸差异，旋转时模型的世界空间中心始终不动。第二、三阶段目标接近第一阶段（例如宽度 0.96、0.88；高度 0.96、0.88），第四阶段仍显著更小，始终不放大源模型。逐阶段截图验证宽高和模型中心稳定。

## 资产与加载

食物清单 `src/data/foods.ts` 保存 id、名字、描述、封面、阶段数组；每阶段含可公开访问的优化版 GLB 地址、八口默认数与展示校准。当前汉堡注册四个文件。食物切换以 id 为会话边界，每种食物独立 AssetStore；仅选中后请求该食物的第一阶段，后续按当前策略后台顺序预载，不跨食物拉取模型。复用成功解析的模型，失败允许重试。今后新食物提供四个阶段 GLB 和一张封面图（建议 WebP）；将源文件放入 `public/models/<food-id>/`，优化版放入 `public/models-mobile/<food-id>/`，注册清单。四个 GLB 能运行游戏，但没有封面会用占位图；供选择界面观感和速度，推荐提供小封面。README 文档描述版本、命名、优化和如何进入游戏。优化脚本应接受食物 id，不能继续写死 burger 四文件。

## 验证

单测覆盖食物配置序列、舞台中心、二三阶段投影、设置持久化。浏览器覆盖选择进入、设置改变和保存、返回选择、拖动中心、直接进食、失败重试与重玩；生成桌面移动截图并检查截图像素、溢出和 JS 错误。生产构建及现有七项端到端测试通过。旧 assets 保留，不撤销既有改动。
